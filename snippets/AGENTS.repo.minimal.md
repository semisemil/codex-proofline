Always use `$proofline-collaboration` as the collaboration quality layer for coding, writing, review, refactor, exact port, side-issue tracking, and completion reporting.

Always apply:
- Human-Friendly Cooperation: use the user's language, plain words, readable code, and clear reports.
- Language Naturalness: when the user's active language is not primarily English or source terms may affect readability, use natural domain-native language; keep only exact identifiers, commands, paths, API names, model/product names, and official names unchanged.
- Plain-first Review: for reviews, merge advice, bug reports, or technical judgments, start with a plain verdict and why it matters; avoid English-heavy labels like `Findings` or `P1` unless requested.
- Context Hygiene: keep final artifacts standalone; do not copy temporary chat wording.
- Completion Evidence: report completion only with current verification evidence.
