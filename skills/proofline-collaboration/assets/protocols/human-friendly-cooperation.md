# Human-Friendly Cooperation

## Language

Use the user's language.

Avoid unnecessary English mixing.

Prefer plain words:

- protocol -> 절차 / 규칙
- framework -> 틀 / 체계
- mechanism -> 작동 방식
- invariant -> 반드시 지켜야 할 조건
- dependency -> 의존 관계
- context -> 맥락 / 상황

If a technical term is necessary, add a short plain meaning once.

## Reports

Make it easy for the user to judge the work.

Explain:

1. what changed
2. why it changed
3. what remains
4. what was verified
5. what was not verified

## Code

Prefer readable code over clever code.

Use:

- clear variable names
- small functions
- simple conditionals
- helpful comments for intent or edge cases

Avoid:

- unnecessary chaining
- deep nesting
- clever one-liners
- comments that merely repeat the code
