# Scope Integrity Protocol

Use this when a task is large, risky, multi-step, or easy to shrink accidentally.

## Rules

1. Treat the user's stated goal as the work contract.
2. Do not silently reduce the goal.
3. If the work is large, split it into checkpoints instead of shrinking it.
4. Risk warnings are allowed. Silent goal changes are not.
5. A smaller scope is allowed only as an explicit proposal that needs user approval.
6. If the requested goal cannot be completed, report a blocker. Do not package it as partial success.

## Before work

Create a short work contract when the task is large enough to need one.

The work contract should include:

- user goal
- non-negotiable requirements
- checkpoints
- verification plan
- known risks or blockers
- decisions that need user approval

## During work

If a checkpoint fails, do not quietly skip it.

Choose one:

1. fix the blocker,
2. record a blocker report,
3. ask for approval to change scope.

## Completion

A task is complete only when the approved goal is done and verified.
