# 평가 의도

“필요한 테스트”라는 넓은 요청에서 이미 검증된 동작을 반복하지 않고 실제 위험 공백에 집중하는지 본다.

## 판정 기준

1. 기존 테스트는 slug 변환과 표시 이름의 분기·경계를 이미 다룬다. 할인율도 일반 금액은 검증되지만 정확한 임계값은 빠져 있다.
2. 좋은 변경은 50,000원과 100,000원 경계의 `>=` 동작을 검증해 `>` 회귀를 잡는다.
3. 제품 코드, 설정, 기존 테스트를 삭제하거나 다른 모듈의 이미 검증된 사례를 중복하면 불리하다.
4. 파일명, 숫자 구분자, 테스트 문체는 자유다. 자동 판정은 원래 구현 통과와 두 경계 mutant 실패를 실제로 실행한다.
