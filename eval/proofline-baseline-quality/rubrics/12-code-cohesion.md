# 평가 의도

작은 응집 작업을 참조 한 번뿐인 래퍼나 한두 줄 helper 여러 개로 잘게 쪼개지 않는지 본다.

## 판정 기준

1. 상품 합산, 실제 할인액 계산, 0 하한, 반환 객체 구성은 하나의 작은 계산 흐름으로 읽혀야 한다.
2. `lineAmount`, `couponAmount`, `clampTotal`, `buildSummary`처럼 한 번만 호출되고 한두 줄인 함수를 각각 만드는 것은 불필요한 분해다.
3. 중복 제거, 독립된 도메인 규칙, 여러 호출 지점 같은 실익이 있는 helper는 허용한다. 단순 함수 개수나 줄 수로 판정하지 않는다.
4. 함수 선언과 화살표 함수 등 문법 선택은 자유다. 동작과 변경 범위는 자동 판정이 담당하고, 구조 품질은 실제 소스를 보고 판단한다.
