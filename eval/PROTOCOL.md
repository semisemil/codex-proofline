# 평가 원칙

이 문서는 Proofline 스킬 평가에 공통으로 적용하는 실행 및 판정 기준을 설명합니다.

## 1. 같은 조건에서 비교합니다

각 사례는 `스킬 미적용`과 `스킬 적용` 두 조건으로 실행합니다.

두 조건에서 다음 항목을 같게 유지합니다.

- 사용자 요청과 작업 파일
- 모델과 추론 강도
- 파일 및 명령 실행 권한
- Codex CLI 버전과 실행 옵션
- 네트워크와 외부 도구 사용 여부
- 반복 횟수

차이는 평가 대상 스킬의 지침 적용 여부뿐이어야 합니다.

## 2. 스킬을 명시적으로 호출합니다

두 조건에는 같은 사용자 요청과 같은 작업 파일을 사용합니다.

- **스킬 미적용:** 대상 스킬을 사용하지 말라는 지시와 사용자 요청을 전달합니다.
- **스킬 적용:** 사용자 요청 앞에 대상 스킬을 사용하고 작업 전에 `.agents/skills`의 전체 `SKILL.md`를 직접 읽으라는 지시를 추가합니다.

각 임시 저장소의 `.agents/skills`에는 같은 버전의 `proofline-baseline-quality` 스킬을 둡니다. 이는 Codex의 저장소 범위 스킬 위치이며 일반 프로젝트 변경 검사에서는 제외합니다. 스킬 미적용 요청에서는 사용하지 말라고 명시해 자동 선택을 막고, 스킬 적용 요청에서만 명시적으로 호출합니다.

이 평가는 Proofline의 설치 과정이나 `SessionStart` Hook을 검증하지 않습니다. 스킬을 명시적으로 사용했을 때 작업 결과가 어떻게 달라지는지만 비교합니다.

## 3. 매번 독립된 세션과 작업공간에서 실행합니다

각 사례와 반복 실행마다 새 Codex 세션과 새 임시 작업공간을 만듭니다. 한 번의 평가 실행에는 인증 정보만 담은 임시 Codex 설정 폴더를 사용하고 실행이 끝나면 삭제합니다.

평가 세션에는 다음 내용을 가져오지 않습니다.

- 기존 대화와 실행 기록
- 사용자의 Codex 설정
- 평가 대상 외에 사용자가 설치한 스킬과 플러그인
- 사용자 및 프로젝트 실행 규칙
- 다른 평가 사례와 이전 결과

모델 호출에 필요한 인증 정보만 제한적으로 전달합니다. 사용자 설정 파일은 복사하지 않으며 인증 값과 전체 환경 변수는 결과에 저장하지 않습니다.

## 4. 실행 전에 격리를 확인합니다

실제 평가를 시작하기 전에 다음 항목을 점검합니다.

1. 두 조건에 같은 버전의 대상 스킬과 같은 작업 파일이 제공되는지 확인합니다.
2. 스킬의 자동 호출이 비활성화됐는지 확인합니다.
3. 스킬 미적용 요청에는 스킬 호출 문구가 없고 스킬 적용 요청에만 있는지 확인합니다.
4. 스킬 적용 실행에서는 대상 `SKILL.md`를 읽고, 스킬 미적용 실행에서는 읽지 않는지 실행 기록으로 확인합니다.
5. 사용자 설정, 사용자 스킬과 다른 프로젝트 규칙이 불러와지지 않는지 확인합니다.
6. 파일 수정 사례에서 작업공간을 실제로 수정할 수 있는지 확인합니다.
7. 네트워크와 외부 MCP 서버가 비활성화됐는지 확인합니다.

점검 결과를 확인하지 못한 실행은 성공이나 실패로 채점하지 않고 `미검증`으로 기록합니다.

## 5. 목적에 맞는 반복 횟수를 사용합니다

| 실행 목적 | 조건별 반복 | 용도 |
| --- | ---: | --- |
| 빠른 점검 | 1회 | 사례와 평가 기준이 제대로 작동하는지 확인 |
| 공개 결과 측정 | 3회 | 저장소의 결과표와 보고서에 게시 |

빠른 점검은 실행 비용을 줄여 문제를 일찍 찾기 위한 용도입니다. 이 결과만으로 스킬이 더 우수하다고 주장하지 않습니다.

공개 결과 측정에서는 사례별로 `스킬 미적용`과 `스킬 적용`을 각각 세 번 실행합니다. Promptfoo가 실제로 실행한 사례와 조건 순서를 결과에 기록합니다. 현재 실행기는 세션 기록이 섞이지 않도록 동시 실행 수를 1로 제한하므로, 이 순서를 공개 결과의 한계와 함께 해석합니다.

상대평가 시에는 두 결과를 A와 B로 표시하고 `미적용/적용`, `적용/미적용` 두 순서로 모두 평가합니다. 두 순서에서 같은 결과를 선택했을 때만 승리로 인정하고, 판정이 달라지거나 의미 있는 차이가 없으면 동점으로 처리합니다. 평가자에게 스킬 적용 여부, 스킬 본문과 기대 결과를 알려주지 않습니다. 평가자는 전체 이유와 기준별 이유를 구조화된 결과로 남깁니다.

## 6. 답변과 실제 작업을 함께 봅니다

각 실행에서 다음 증거를 수집합니다.

- 최종 답변
- 실행한 명령과 종료 코드
- 파일 생성, 수정 및 삭제 내역
- 도구 호출 내역
- 실행 완료 또는 실패 상태
- 입력 및 출력 토큰 사용량

파일 작업 사례는 답변에서 “수정했다”고 말한 것만으로 통과하지 않습니다. 실행 전후의 파일 목록과 SHA-256을 비교해 실제 변경을 확인합니다.

## 7. 중요한 실패를 먼저 판정합니다

각 사례의 평가 기준은 `중대 기준`과 `보조 기준`으로 나눕니다.

- **중대 기준:** 의미 왜곡, 허용되지 않은 변경, 필수 검증 실패처럼 결과를 사용할 수 없게 만드는 항목
- **보조 기준:** 자연스러움, 간결성, 설명 품질처럼 결과의 완성도를 비교하는 항목

중대 기준 하나라도 실패한 실행은 중대한 실패로 처리합니다. 보조 점수가 높아도 이를 상쇄할 수 없습니다.

스킬 적용 결과는 다음 조건을 모두 만족할 때만 해당 평가 세트에서 개선된 것으로 표시합니다.

1. 스킬 적용 후 새로운 중대 실패 유형이 생기지 않았습니다.
2. 어떤 중대 사례에서도 스킬 미적용 결과보다 통과 횟수가 낮지 않습니다.
3. 전체 중대 실패 횟수가 줄었습니다.

그 외에는 `판단 보류` 또는 `회귀`로 표시합니다.

## 8. 결과를 재현할 수 있게 기록합니다

결과에는 다음 정보를 포함합니다.

- 평가 세트 버전과 평가 대상 스킬 SHA-256
- 모델과 추론 강도
- Promptfoo, Codex SDK와 Node.js 버전
- 권한 및 네트워크 설정
- 반복 횟수와 실제 실행 순서
- 원시 결과 SHA-256
- 사례별 원시 결과, 검사 결과와 판정 이유

공개 사례에 맞춰 스킬을 과도하게 조정할 수 있으므로, 결과는 해당 평가 세트 안에서의 비교로만 해석합니다.
