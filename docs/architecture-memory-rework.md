# 아키텍처 메모리 개편 및 비용 분석

## 적용 결과

목표는 코드만으로 복원할 수 없는 사용자 결정·선택 이유·현장 운영 조건을 보존하고, 필요한 개발 판단에서 해당 근거를 찾아 적용하는 것이다. `architecture-memory`, `architecture-memory-init`, `architecture-memory-update`와 직접 사용하는 도구·훅을 개편했다. 기존 동작 보존을 위한 리팩터링이 아니라 사용자가 승인한 재설계다.

문서 구조는 C4 L1·L2, 필요한 L3, 현재 맥락과 근거 있는 ADR을 유지한다. [사용자가 제공한 영상](https://www.youtube.com/watch?v=LaLtZsRWFMc)의 C4·ADR·arc42를 함께 사용하되 필요한 수준만 유지한다는 방향을 따른다. 코드 관찰과 사용자 이유, 제안과 수락된 계획, 현재 구현과 이력을 구분한다.

## 호출과 저장

초기화 전에는 세 스킬의 전역 암시 호출이 꺼져 있다. 훅은 프로젝트와 제한된 상위 경로에서 `.proofline/architecture.json`의 존재만 확인한다. 없으면 문서 탐색·스킬 읽기·연결 알림 상태 저장을 하지 않고 모델에 아무 내용도 출력하지 않는다. 이는 메모리 훅의 출력에 대한 보장이다. 호스트의 전체 스킬 목록 비용이나 훅 프로세스 실행 비용이 0이라는 뜻은 아니다.

초기화 성공 후 연결 파일에는 상대 문서 위치만 저장한다. 훅이 현재 설치된 플러그인의 스킬 경로를 해석하고 세션/에이전트별 중복 알림을 억제한다. 컨텍스트 초기화·압축, 설치 위치나 활성 상태 변경 시 필요한 연결을 다시 전달한다. 기존 AGENTS의 표시된 메모리 연결 블록만 제거하고 다른 지침은 유지한다. 훅을 지원하지 않거나 식별자가 없는 환경에서는 명시적으로 호출해야 한다.

저장 책임은 다음과 같다.

| 데이터 | 저장 위치 | 유지 방식 |
| --- | --- | --- |
| 사람과 에이전트가 공유하는 사실·제약·결정 | 등록된 Markdown | 주제별 H2 절, 안정 ID·경로·별칭·필수 참조; 대화 원문을 중복 저장하지 않음 |
| 관리·문서 등록·Git 기준점 | `.architecture-memory/manifest.json` | 기존 v2 형식 유지; 체크포인트는 update 도구 소유 |
| 프로젝트 연결 | `.proofline/architecture.json` | 상대 메모리 위치만 저장; 문서와 함께 버전 관리 |
| 진행 중 작업과 복구 | `.architecture-memory/work/` | 초안·분류·파일별 반영 기록; 한 작업의 상태를 유지하고 다음 작업에서 교체; 로컬 `.gitignore`로 커밋 제외 |
| 연결 중복 억제 | 플러그인 로컬 데이터 또는 임시 경로 | 세션/에이전트와 연결 상태의 해시; 대화 내용은 저장하지 않음 |

별도 DB·임베딩·검색 인덱스는 없다. 검색마다 등록 문서를 로컬 디스크에서 읽어 원본 변경을 바로 반영한다. 모델에는 후보 위치와 선택한 절만 전달한다. 문서량에 따른 디스크 읽기 비용과 초안·반영 기록의 로컬 사본 비용은 남는다.

## init·update의 구조 수정

| 확인한 문제 | 변경한 실행 경로 |
| --- | --- |
| 미커밋 코드로 문서를 쓰고 HEAD를 체크포인트로 기록 | 시작 시점의 커밋에서 source/diff를 읽음. HEAD나 작업 파일이 바뀌어도 기준점 유지 |
| 부분 수정 후 깨끗한 작업 트리를 요구해 복구 불가 | 실제 문서 대신 초안 작성, 검사 후 반영. 중단 시 전후 해시로 이미 반영된 파일과 남은 파일 구분 |
| `managed: true`만으로 완료 간주 | 기본 종류의 문서 5개에 본문이 있고 등록·라우팅·필수 참조가 유효해야 초기화 반영 가능 |
| 설치 캐시의 절대 경로를 AGENTS에 저장 | 상대 루트의 프로젝트 연결과 현재 설치 경로를 해석하는 훅으로 변경 |
| 독립 실행의 병렬 source 읽기가 작업 잠금과 충돌 | 커밋이 고정된 읽기는 잠금 없이 병렬 실행; 관찰 상태를 쓰는 무커밋 경로만 잠금 사용 |

Git 커밋이 없는 초기화는 관찰한 파일의 해시와 목록 변화를 검사하며 체크포인트를 null로 유지한다. 소스가 바뀌면 해당 근거를 refresh하고 초안의 관련 주장을 재검토할 수 있다. 최초 커밋 이후 update가 현재 기준선을 한 번 대조한다.

update는 관련 경로를 분류하고 그 결과를 저장한다. 동일 커밋과 메모리 문서만 바뀐 구간은 문서 읽기 없이 종료한다. 코드 변경을 모두 검토했다면 문서 수정이 없어도 체크포인트를 전진시킨다. 분기 변경은 스냅샷 차이로 취급하며 커밋 순서에서 결정 역사를 추정하지 않는다.

여러 파일 반영은 파일시스템 전체의 원자적 교체가 아니다. 중단 시 문서와 체크포인트가 일부 반영될 수 있지만 `applying` 상태가 남으며 메모리 조회 도구는 읽기를 거부한다. 재실행은 같은 작업을 완료한다. 외부 편집은 보존하고 해당 충돌을 해결하기 전 완료로 보고하지 않는다. Dashboard는 기존의 읽기 전용 파일 뷰이므로 중단 상태에서 화면에 보이는 파일을 완료 판정 근거로 삼지 않는다.

## 토큰 증가 위험과 대응

| 증가 경로 | 적용한 대응 | 남는 비용 또는 한계 |
| --- | --- | --- |
| 매 작업에서 전체 문서·템플릿 읽기 | 주제/경로 검색 → 선택한 절; 조건부 참조; 이미 아는 안정 ID는 직접 읽기 | 작은 문서에서는 검색·JSON 포장이 원문보다 비쌈 |
| 대화마다 연결·공통 제약 반복 | 연결 알림 중복 억제; 그대로 남은 근거는 호출 없이 재사용; 다른 소유자의 문맥을 읽을 때 공통 절 receipt 사용 | 컨텍스트 소실 후에는 다시 읽어야 함. receipt만 전달하면 근거가 되지 않음 |
| 필수 링크 연결이 커지거나 전역 제약이 비대해짐 | `always`는 짧은 실제 공통 제약만; 완전한 절을 페이지 단위로 전달; 같은 조회는 짧은 cursor로 이어 읽기 | 필요한 연결 전체의 크기는 줄이지 않음. 문맥 수용 범위를 넘으면 관련 판단이 미해결임을 명시 |
| 전체 diff 출력·같은 경로 재분류 | 목록과 개수부터 확인, 관련 소스의 제한된 범위만 읽기, 근거 있는 동질 집합은 일괄 분류 | 분류를 위한 실제 근거는 필요하며 디렉터리 이름만으로 무관하다고 판단하지 않음 |
| 실패 때 모든 근거·검사 재수행 | 초안·분류·반영 기록 재사용, 실패한 부분만 복구; apply의 구조 검사를 따로 반복하지 않음 | 외부 편집 충돌과 새로운 근거는 재판단 필요 |

검색 실패는 한 번의 근거 있는 용어/경로 재구성 뒤에도 필요한 맥락이 없으면 코드나 사용자 근거로 해결한다. 무한 재검색·전체 문서 덤프로 대신하지 않는다. 검색 결과 부재는 제약 부재의 증거가 아니다.

출력 상한은 응답 하나에 적용된다. 검색 기본 6,000자, 절 읽기 기본 12,000자·최대 32,000자, 소스 본문 8,000자, 변경 경로 페이지 5,000자이며 JSON 문자 수 기준이다. 작업·에이전트 수, 대화 길이, 실제 필요한 근거량에 따른 총토큰 상한은 보장하지 않는다.

## 측정

[스킬 프롬프트 작성 원칙](skill-prompt-authoring-principles.md)에 따라 본문과 유발되는 입출력, 정상과 실패 경로를 분리했다. 현재 작업을 시작할 때 저장한 실제 프롬프트와 비교했으며 Git HEAD를 수정 전 상태로 가정하지 않았다. 토크나이저는 `o200k_base`; 원시 결과와 수정 전 파일 해시는 [측정 자료](architecture-memory-costs.jsonl)에 있다.

| 읽는 지침의 범위 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| memory 진입점 | 508 | 473 |
| 기존 절의 대화 기록: 진입점 + recording | 1,589 | 959 |
| 새 절의 대화 기록: 위 경로 + 필요한 서식 | 1,589 | 1,328 |
| 기본 init: 진입점 + 초기화 + 기록 + 서식 + 기본 템플릿 | 3,744 | 2,723 |
| 일반 update: 진입점 + retrieval + recording | 2,578 | 1,649 |

기본 템플릿은 전후 공통 977토큰이다. 선택적 L3·ADR 템플릿, 실패 시 workflow 상세 818토큰, 실제 프로젝트 근거와 작성 출력은 위 표에 포함하지 않았다. init 진입점 자체는 86→294토큰으로 늘었지만, 초기화 본문과 함께 읽는 경로는 줄었다. 파일 하나의 길이만으로 개선을 판정하지 않았다.

| 합성 자료·측정 경로 | 결과 |
| --- | --- |
| 관련 문서 1개 + 무관한 문서 80개 | 전체 Markdown 61,895토큰; 검색·읽기 출력 328토큰; memory 진입점까지 801토큰 |
| 55토큰짜리 문서 1개 | 검색·읽기 출력 320토큰: 작은 원문보다 비쌈 |
| 공통 제약을 공유하는 소유자 5개 | 요청·응답 합계 5,064→2,268토큰; 각 소유자 근거와 공통 제약 유지 |
| 필수 연결 26절, 6,000자 페이지 | receipt 누적 20,362→cursor 13,683토큰; 13번 호출에서 26절 모두 전달 |
| 초기화 전 20번 훅 호출 | 메모리 연결 출력 0토큰 |
| 초기화된 같은 세션의 20번 훅 호출 | 첫 연결만 출력, 합계 56토큰 |

연결이 많은 예제의 원문은 7,527토큰이다. cursor 적용 후에도 왕복 13,683토큰으로 더 크다. 페이지별 JSON·출처·미완료 보고와 절별 식별표 비용을 포함하기 때문이다. 전체 연결이 필요한 문제를 무조건 저렴하게 처리한다고 주장하지 않는다. receipt를 같은 조회의 페이지마다 누적하는 전략은 요청만 7,741토큰으로 커져, cursor의 1,053토큰으로 교체했다.

상태 도구의 입출력만 별도로 측정하면 같은 커밋 확인은 1회·42토큰, 300개 고정 테스트 자료의 일괄 분류는 4회·657토큰이다. 부분 반영 후 재개는 2회·161토큰이며 기존 분류·코드 근거를 다시 출력하지 않았다. 이 수치는 아키텍처 해석, 문서 작성, 문서 검색, 모델 추론과 검사 결과를 모두 합한 작업 비용이 아니다.

재현 명령:

```text
python tests/benchmarks/architecture-memory.py
node --test tests/architecture-memory-workflow.test.js tests/architecture-memory-retrieval.test.js
```

`tiktoken`이 필요하다. 수정 전 사본이 있으면 `--before-dir <path>`를 추가한다. 커밋 해시·임시 경로·실행 시간에 따라 일부 수치가 조금 달라질 수 있다. 현재 결과는 Windows 로컬 실행이다.

## 검증과 판정 범위

전체 `npm test`: 348개 통과. 이후 조회 상태·receipt 판별 보강을 포함한 관련 검사 46개도 통과했다. 세 스킬의 형식 검사와 변경 diff 공백 검사도 통과했다. 초기화 준비 상태, 미커밋 변경, 최초 커밋, 동일 커밋, 문서만 변경, 이름 변경, 분기 전환, 부분 반영, 외부 편집, 잘못된 상태·경로, 병렬 소스 읽기, 훅 연결, 검색·필수 연결·재사용·cursor와 기존 Dashboard API를 검사했다. 프롬프트의 문자열만 확인하는 검사를 줄이고 실제 생성·조회·실패·재개 결과를 검사한다.

독립 실행에서 임시 공장 프로젝트의 문서 5개와 연결을 만들었다. 망 점검 중 접수 유지, 야간 관리자 부재와 재부팅 불가, 사무실 화면 제외, 디스크 저장 미결정을 출처와 범위를 붙여 기록했다. 미커밋 실험 주석을 기준선에 섞지 않았다. 후속 update는 이름이 바뀐 사무실 API의 경로를 갱신하면서 사용자 운영 조건과 미결정 상태·검증 필드를 유지했다. 결과 문서와 체크포인트를 별도로 확인했다. 등록은 임시 APPDATA에만 수행했다.

이 검증은 구현의 결과와 독립 실행 사례에 대한 근거다. 동일 모델·추론 수준의 무스킬 대조군을 포함한 장기 품질 우위, 다국어 검색 재현율, 대화 기록 누락률은 측정하지 않았다. 실제 API의 비캐시 입력·캐시 입력·캐시 쓰기·추론/출력 및 최상위·하위 작업별 청구 사용량도 확보하지 못했다. 따라서 실과금 절감률이나 무스킬 대비 총비용·품질 우위를 주장하지 않는다.

변경은 Proofline 개발 저장소에 반영했다. 설치 캐시 갱신과 배포는 포함하지 않았다.
