# 아키텍처 메모리 상태 처리와 비용 개선

## 작업 계약

사용자 승인 범위: 검토한 init/update의 네 구조 문제를 수정하고, 스킬 본문뿐 아니라 유발되는 탐색·출력·재실행 비용을 분석·개선한다. 기존 비관련 변경은 유지하며 추가 승인을 요구하지 않는다.

완료 조건: 초기화 전 메모리 스킬 자동 호출 없음, 기계별 설치 경로를 프로젝트에 저장하지 않음, 코드 기준선과 체크포인트 일치, 불완전한 초기화의 완료 판정 방지, 부분 반영 후 재개 및 타인 변경 보존, 작업별 출력 상한과 재사용 경로.

## 책임 변경

| 책임 | 현재 | 변경 후 |
| --- | --- | --- |
| 상태·기준점 | 프롬프트가 Git과 manifest를 수동 해석 | 실행 도구가 고정된 소스 기준·진행 기록·체크포인트 소유 |
| 반영·복구 | 실제 문서 수정 후 실패 시 미완료 파일 잔존 | 초안 검사 후 반영, 파일별 전후 상태 비교로 안전하게 재개 |
| 프로젝트 연결 | AGENTS에 설치본 절대 경로 | 프로젝트에는 상대 메모리 위치만 저장, 플러그인이 현재 설치 위치를 해석 |
| 근거·본문 | 에이전트 작성 | 유지: 사용자 발언·코드 관찰·추론·계획을 구분하여 작성 |
| 읽기 비용 | 재조사·예산 증가·연결 문서 반복 가능 | 판정·읽기 결과 재사용, 페이지·문단 단위의 명시적 미완료와 종료 조건 |

## 검증 순서

1. 초기화: 미커밋 코드 제외 또는 무커밋 기준의 명시적 구분, 필수 문서 준비 상태, 초기화 전 훅 출력 없음.
2. 갱신: 정상·변경 없음·문서만 변경·최초 커밋·분기 변경에서 고정된 Git 범위와 올바른 체크포인트.
3. 반영: 작성 실패·부분 반영·재실행·외부 편집에서 범위 보존과 복구.
4. 비용: 정상·다수 파일·문서 연결 확장·검색 실패·재실행의 본문 및 도구 출력량, 반복 배수와 측정 불가능한 과금 항목을 구분.
5. 실제 인터페이스 회귀 및 독립 실행. 각 결과의 검증 범위를 제한해 보고.

## 비용 판정

`skill-prompt-authoring-principles.md`를 적용한다. 낮은 토큰 수만으로 품질을 판정하지 않는다. 가능한 항목은 고정된 검사로 결과를 비교하고, 실제 모델의 캐시 입력·출력·추론·하위 작업 과금 내역이 없으면 측정하지 못했다고 명시한다. 시뮬레이션 출력 토큰을 실제 API 비용으로 환산하지 않는다.

## 완료 기록

상태 처리 도구, 초안 반영·재개, 상대 루트 연결 훅, 제한된 검색·소스 출력과 근거 재사용을 구현했다. 독립 초기화 실행에서 발견한 병렬 소스 읽기의 잠금 충돌을 수정했고, 연결이 많은 조회의 receipt 누적 비용을 측정한 뒤 같은 조회의 페이지는 짧은 cursor로 변경했다.

전체 저장소 테스트 348개, 마지막 조회 보강 후 관련 검사 46개 통과. 독립 초기화 및 후속 Git 갱신의 문서·사용자 맥락·체크포인트를 확인했다. 수정 전후 지침과 유발되는 입출력, 실패 후 재개, 실제 과금과 품질 비교의 미측정 범위는 [최종 분석](architecture-memory-rework.md)에 기록했다. 배포와 설치 캐시 변경은 범위 밖으로 유지했다.
